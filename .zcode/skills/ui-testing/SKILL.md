# Тестирование интерфейса

Проверка UI UniCalendar выполняется в реальном браузере. Основной инструмент агента — **Playwright MCP**; автотесты — **Playwright** (Vitest/Playwright Test).

## Инструменты Playwright MCP

- Открытие страницы: `browser_navigate` → структура DOM и доступность: `browser_snapshot` (дерево доступности — основной способ чтения страницы, предпочтительнее скриншотов).
- Действия: `browser_click`, `browser_type`, `browser_fill_form`, `browser_press_key`, `browser_hover`, `browser_select_option`, `browser_wait_for`.
- Проверка вида: `browser_take_screenshot`; размеры: `browser_resize`; эмуляция темы: `browser_emulate_media` (colorScheme light/dark).
- Диагностика: `browser_console_messages` (ошибки JS), `browser_network_requests` (упавшие запросы).

## Чек-лист проверки UI

- **Desktop и mobile**: проверь макет на десктопном размере (например 1280×800) и мобильном (например 375×812). Нет горизонтального скролла, элементы не перекрывают друг друга, меню доступно.
- **Консоль браузера**: ошибок JavaScript нет. Предупреждения hydration/SSR — тоже ошибка, которую надо устранять.
- **Загрузка страницы**: страница отрисовывается без «вечной загрузки»; сетевые запросы без 4xx/5xx.
- **Формы**: валидация работает (пустые/некорректные значения не отправляются), ошибки показываются пользователю, после отправки — корректное состояние.
- **Кнопки**: доступность (disabled во время загрузки, повторное нажатие не дублирует действие), состояния hover/active.
- **Тёмная и светлая тема**: обе темы читаемы, текст не теряет контраст, компоненты Nuxt UI не «ломаются».
- **Доступность**: у интерактивных элементов есть понятные имена в accessibility-дереве; навигация с клавиатуры работает; семантические заголовки.

## Цикл работы

1. Найди ошибку в браузере → зафиксируй шаги воспроизведения.
2. Исправь код.
3. **Повторно прогони тот же сценарий** в браузере и убедись, что ошибка ушла и ничего нового не появилось.
4. Для регрессий пиши E2E-тесты на Playwright, чтобы ошибка не вернулась.

## Запрещено

- Заявлять «интерфейс работает», не открыв его в браузере или не прогнав E2E-тесты.
- Проверять только desktop и игнорировать mobile-вьюпорт.
- Игнорировать ошибки в консоли браузера, если они воспроизводятся.
- Отчитываться о пройденных тестах, которые не были запущены.
