# Google OAuth 2.0 и Google Calendar API

Skill описывает безопасную интеграцию с Google для UniCalendar (ручная синхронизация расписания в Google Calendar).

## OAuth 2.0

- Flow — **Authorization Code** для веб-приложения. Реализация на серверной стороне Nitro.
- Всегда передавай и проверяй параметр **`state`** (случайная строка в сессии): совпадение — обязательное условие обработки callback. Несовпадение = отказ.
- Применяй **PKCE** (`code_verifier` + `code_challenge`, S256), если используемая библиотека/эндпоинт это поддерживает.
- `redirect_uri` должен строго совпадать с зарегистрированным в Google Cloud Console: для production — `https://calendar.dmbugaev.ru/api/auth/google/callback` (или согласованный маршрут), для локальной разработки — свой localhost-URI.
- Не собирай лишние scopes. Минимальный набор для проекта:
  - `https://www.googleapis.com/auth/calendar.events` — чтение и запись событий;
  - `https://www.googleapis.com/auth/calendar` — управление календарями (нужен для создания отдельного календаря расписания).
- Access token никогда не попадает в клиентский код, URL или логи.

## Токены

- **Refresh token** храни только на сервере (PostgreSQL), с доступом строго по идентификатору пользователя; не пиши его в cookie, localStorage, логи и репозиторий.
- Учитывай истечение access token (~1 час): обновляй заранее или обрабатывай `401` повторным обновлением.
- Обязательна обработка отзыва/недействительности refresh token (`invalid_grant`) — приглашение пользователя повторно войти.
- Для повторного получения refresh token при повторной авторизации отправляй `prompt=consent` (и `access_type=offline`).

## Google Calendar API

- Создание отдельного календаря расписания — через `calendars.insert` (свойство `summary`, например «Расписание 251-362»). Идентификатор созданного календаря сохраняй в БД.
- События — `events.insert` / `events.update` / `events.delete` с указанием `calendarId`.
- Для сопоставления событий с расписанием вуза используй `extendedProperties.private` (см. skill `safe-calendar-sync`).
- Уважай часовые пояса: события создавай с явным `timeZone` (`Europe/Moscow`), а не со смещением «наугад».

## Ошибки и квоты

Обрабатывай ошибки Google API явно:

| Статус | Причина | Действие |
|---|---|---|
| 401 | access token истёк/недействителен | обновить токен и повторить запрос один раз |
| 403 `rateLimitExceeded` / `quotaExceeded` | превышение квоты | экспоненциальная задержка + повтор |
| 403 `calendarUseRevoked` | отзыв доступа | пометить интеграцию неактивной, попросить повторную авторизацию |
| 404 | календарь/событие удалено | пометить расхождение в журнале, не падать |
| 5xx | сбой на стороне Google | повтор с экспоненциальной задержкой, ограничить число попыток |

- Повторы — с экспоненциальной задержкой и джиттером, ограниченным числом попыток. Не зацикливай запросы.
- Перед реализацией конкретных методов API проверяй актуальную документацию через **Context7 MCP** (библиотека Google Calendar API / googleapis). Не выдумывай поля и эндпоинты.

## Запрещено

- Хранить `client_secret`, токены и ключи в репозитории, клиентском бандле или public-каталоге.
- Запрашивать scopes за пределами перечисленных (например, полный доступ к Drive или почте).
- Логировать тела ответов с токенами или персональными данными.
