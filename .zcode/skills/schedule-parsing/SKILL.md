# Парсинг расписания Московского Политеха

Источник расписания — сайт вуза (`rasp.dmami.ru`), группа **251-362**. Данные нужны для синхронизации в Google Calendar.

## Главный запрет

**Никогда не выдумывай endpoints, параметры и форматы ответов.** Каждый используемый URL и поле ответа должны быть проверены реальным запросом в этой же сессии. Если структура неизвестна — сначала исследование (см. ниже), потом код.

## Порядок исследования

1. Открой сайт расписания в браузере через **Chrome DevTools MCP** (`list_network_requests`, `get_network_request`) и определи, какие запросы уходят за расписанием группы.
2. Проверь, есть ли документированный/публичный API (страницы документации, описания API вуза). Если есть — используй его.
3. Сохрани реальный JSON-ответ в файл примера (fixture) и анализируй структуру по нему, а не по предположениям.
4. Если API нет — разбор HTML через регулярные выражения/парсер по фактической разметке, сохранённой в fixture.

## Анализ данных

- Валидируй ответ источника **Zod-схемой**. Невалидный ответ = остановка синхронизации с понятной ошибкой, а не частичный импорт.
- **Нормализация дат**: приведи все даты/время к однозначному виду (ISO 8601, часовой пояс `Europe/Moscow`). Явно учитывай формат дат источника (например, `DD.MM.YYYY`).
- **Чётные/нечётные недели**: определи по фактическим данным источника, как он обозначает номер недели или чередование; вычисли привязку к календарным датам и зафиксируй правило в коде с комментарием.
- **Отменённые занятия** и **переносы**: если источник их помечает — учитывай признаки явно (отдельное поле/флаг), не смешивай с обычными занятиями.
- Проверяй полноту: все ли дни/пары диапазона присутствуют; отсутствие ожидаемого дня недели — повод для проверки, а не для молчаливого пропуска.

## Защита от изменения структуры источника

- Разбор данных — в отдельном модуле парсера, изолированном от логики синхронизации.
- Пиши unit-тесты (Vitest) на fixture из реального ответа источника.
- При изменении структуры источника парсер должен падать с ясной ошибкой («неизвестное поле/структура»), а не выдавать тихо неверные данные.
- Признаки «источник изменился»: пустые ответы, новые/исчезнувшие поля, неожиданные типы. В этих случаях останавливайся и сообщай пользователю на русском.

## Запрещено

- Вшивать в код предположения о структуре ответа без fixture.
- Парсить «на глаз» по памяти о сайте.
- Молча пропускать нераспознанные занятия.
- Запускать массовую синхронизацию в Google Calendar на непроверенных данных (см. skill `safe-calendar-sync`).
