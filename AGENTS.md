# Правила проекта UniCalendar

Проект: UniCalendar — ручная синхронизация расписания Московского Политеха (группа 251-362) с Google Calendar.
Production domain: https://calendar.dmbugaev.ru

## Язык общения и документации

1. Всегда отвечай пользователю на русском языке.
2. Планы реализации, отчёты о работе и объяснения — на русском.
3. Ошибки и способы их устранения описывай на русском (цитаты логов и англоязычные сообщения сохраняй как есть, но объясняй их смысл по-русски).
4. Проектную документацию создавай на русском.
5. Названия переменных, функций, файлов, классов, API, команд CLI и имён инструментов сохраняй на английском — технические идентификаторы не переводить.
6. Если внешний инструмент (MCP, CLI, тесты) вернул английский текст, объясняй его смысл пользователю на русском.

## Работа с документацией и API

- Перед реализацией сложных функций проверяй актуальную документацию через **Context7 MCP** (Nuxt, Vue, Nitro, Nuxt UI, Tailwind CSS, Drizzle ORM, Supabase, Google Calendar API, Zod, Vitest, Playwright).
- Не выдумывай API, endpoints, параметры и поля ответов. Любое предположение о внешнем API проверяй реальным запросом или документацией.
- Не используй устаревшие подходы без веской причины; при выборе между вариантами предпочитай современный официально поддерживаемый.

## Технологический стек

- Предпочитай Nuxt 4 и Vue 3 (Composition API, `<script setup>`), Nitro для backend, Tailwind CSS + Nuxt UI для интерфейса.
- **Не используй React, Next.js и JSX** — проект на Vue.
- Следуй существующей архитектуре проекта; не вводи новые слои и библиотеки без необходимости и согласования.
- TypeScript strict обязателен; `any` избегай.

## Безопасность и данные

- Не храни секреты (ключи, токены, пароли) в репозитории, клиентском коде и конфигах, попадающих в бандл. Только environment variables / серверное окружение.
- Не выполняй разрушительные операции (удаление файлов, веток, данных БД, `git reset --hard`, force push) без явного подтверждения пользователя.
- Не удаляй пользовательские данные (события календаря, записи БД) без подтверждённых оснований. При работе с Google Calendar соблюдай правила skill `safe-calendar-sync`.
- Не передавай секреты внешним инструментам и сервисам.

## Проверка результата

- После каждого изменения проверяй результат: запусти тесты/сборку/приложение — в зависимости от того, что затронуто.
- Не заявляй об успешном тестировании, если тесты не были запущены. Фактический вывод тестов важнее предположений.
- Ошибки интерфейса проверяй в реальном браузере (Playwright MCP / Chrome DevTools MCP), включая desktop и mobile viewport.

## Коммуникация

- Блокирующие проблемы (недоступные сервисы, нехватка доступов, внешние сбои) объясняй пользователю на русском и предлагай конкретный способ их устранения.
- Работу по проекту веди с учётом проектных Skills в `.zcode/skills/` — они уточняют правила для отдельных областей (разработка, OAuth, парсинг расписания, синхронизация, БД, тестирование, деплой).
